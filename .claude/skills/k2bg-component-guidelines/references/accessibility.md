# Accessibility

The design-system accessibility source is `packages/ui/src/guidelines/Accessibility.mdx`. Preserve its semantics, keyboard operation, and focus requirements in wrappers and app composition.

## Roles and Names

- Use native semantics and the Base UI primitive's role. Navigation stays a link; actions stay buttons. Avoid nested interactive elements.
- Give interactive controls an accessible name. Text content, associated labels, `aria-label`, or `aria-labelledby` supply the name; icon-only naming follows `.claude/rules/code-style.md`, "Accessibility".
- Associate form labels, required state, descriptions, and errors with the control. Preserve the IDs and ARIA relationships generated by headless primitives.
- Keep decorative images/icons out of narration and provide meaningful alternatives for informative media. Preserve a logical heading hierarchy and landmarks.

For example, an icon-only dismiss button has an accessible name such as "Dismiss notification", and an anchor styled with `buttonVariants` retains link semantics. A dialog uses Base UI Title and Description; hiding the title visually does not remove its accessible name.

## Keyboard and Focus

Every interaction supports keyboard operation with logical tab order. Preserve the primitive's arrow-key navigation, selection, escape, disabled state, and focus restoration where applicable. Modal dialogs manage focus and isolate background interaction through the headless primitive; do not replace that behavior with styling alone.

For example, a named combobox supports Tab, ArrowDown, Enter, popup dismissal, and returned focus. Use the primitive's interaction model rather than adding competing keyboard handlers.

Focus appearance, forced-colors support, contrast, and reduced motion follow `k2bg-css-guidelines`. Assertions about accessible roles/names and interaction outcomes follow `.claude/rules/unit-test-guidelines.md`; Storybook content follows `k2bg-storybook-docs`.
